# PACK.IT RUN — Technical Spec v0.1

Дата фиксации: 2026-06-03

## 1. Цель v0.1

v0.1 должен дать первый рабочий игровой каркас, который можно открыть в браузере и реально пройти короткий забег.

Минимальный результат:

```text
Открываешь игру → видишь главное меню → выбираешь уровень → запускаешь забег → управляешь хомяком по трём псевдо-изометрическим дорожкам → собираешь хлеб и ресурсы → ловишь столкновения → доходишь до финиша → получаешь результат → прогресс сохраняется.
```

v0.1 не должен быть финальной игрой, но архитектура не должна быть одноразовой времянкой.

## 2. Стек

На старте используем простой браузерный стек без тяжёлого движка и сборщика:

```text
HTML
CSS
JavaScript modules
Canvas 2D
localStorage
```

Не используем на v0.1:

- Unity;
- Godot;
- Phaser;
- React;
- Vite;
- TypeScript;
- сервер;
- авторизацию;
- онлайн-лидерборд.

Сборщик можно добавить позже, когда проект вырастет.

## 3. Экраны v0.1

Обязательные экраны:

```text
MainMenuScreen
LevelSelectScreen
GameScreen
ResultScreen
```

### MainMenuScreen

Кнопки:

```text
Играть
Уровни
Склад — скоро
Магазин — скоро
Настройки
```

На v0.1 `Склад` и `Магазин` можно показывать как заблокированные / скоро.

Главное меню должно сразу держать будущую структуру игры, чтобы потом не перестраивать навигацию.

### LevelSelectScreen

Карточки уровней:

```text
1. ДК “Почти готово”
2. Свадьба в шатре
3. Большой концерт
4. Детская комната: Генеральная уборка невозможна
```

На v0.1 доступен только первый уровень. Остальные карточки показываются, но заблокированы.

Для разработки можно заложить внутренний dev-флаг, который позволяет тестировать все уровни, но не показывать его обычному игроку.

### GameScreen

Игровой экран с HUD, canvas и нижней строкой событий / подсказок.

Схема:

```text
┌─────────────────────────────────────────────┐
│ Верхняя HUD-панель                           │
│ Хлеб | Ресурсы | Косяки | Прогресс уровня    │
├─────────────────────────────────────────────┤
│                                             │
│             игровая зона canvas             │
│                                             │
│     дальняя дорожка                         │
│        средняя дорожка                      │
│           ближняя дорожка                   │
│                                             │
├─────────────────────────────────────────────┤
│ Нижняя подсказка / событие / фраза           │
└─────────────────────────────────────────────┘
```

HUD v0.1:

```text
Хлеб: 0
Ресурсы: 0 / 10
Косяки: 3
Прогресс: 0–100%
```

### ResultScreen

Показывает итог уровня:

```text
название уровня
собранный хлеб
собранные ресурсы
оставшиеся косяки
процент выполнения
оценка S/A/B/C/D
вердикт / смешная фраза
кнопка повторить
кнопка к уровням
кнопка дальше, если открыт следующий уровень
```

## 4. Управление

### Desktop

```text
A / ←             ближе к игроку
D / →             дальше от игрока
W / ↑ / Space     прыжок
S / ↓             подкат
Esc / P           пауза
Enter             подтвердить / старт
```

### Mobile / Touch

```text
свайп вверх       прыжок
свайп вниз        подкат
свайп влево       ближняя дорожка
свайп вправо      дальняя дорожка
тап               подтвердить / старт
```

Mobile-режим на v0.1 — landscape-first. Вертикальный layout не является задачей v0.1.

## 5. Логика дорожек

Три логические дорожки:

```text
0 — дальняя
1 — средняя
2 — ближняя
```

Визуальная логика:

```text
дальняя — выше на экране, чуть меньше
средняя — центр
ближняя — ниже на экране, чуть крупнее
```

Смена дорожки должна быть плавной и диагональной, чтобы поддерживать ощущение псевдо-изометрии.

## 6. Игрок

Состояния игрока:

```text
running
jumping
sliding
hit
finished
```

Базовая модель:

```js
{
  lane: 1,
  targetLane: 1,
  yJump: 0,
  isJumping: false,
  isSliding: false,
  mistakesLeft: 3,
  invulnerableMs: 0
}
```

Логика:

- игрок всегда находится в фиксированной зоне слева / центр-слева;
- мир и объекты движутся справа налево;
- игрок может менять дорожку, прыгать и подкатываться;
- после удара есть короткая неуязвимость.

## 7. Объекты v0.1

Нужны три базовых типа:

```text
collectible
obstacle
finish
```

Но модель должна быть расширяемой под будущие типы:

```text
powerup
event
bossProjectile
decoration
```

Пример объекта:

```js
{
  id: "bread",
  type: "collectible",
  lane: 1,
  x: 900,
  resource: "bread",
  value: 1,
  visualKey: "bread"
}
```

Пример препятствия:

```js
{
  id: "case",
  type: "obstacle",
  lane: 2,
  x: 1100,
  dodge: "jump",
  damage: 1,
  visualKey: "flight_case"
}
```

## 9. Уровни v0.1

В данных должны быть заведены все четыре уровня, но полноценно доступен только первый.

### Доступен

```text
ДК “Почти готово”
```

### Заблокированы до прохождения

```text
Свадьба в шатре
Большой концерт
Детская комната: Генеральная уборка невозможна
```

Пример конфига первого уровня:

```js
{
  id: "dk_almost_ready",
  title: "ДК “Почти готово”",
  theme: "dk",
  duration: 90,
  speed: 260,
  targetResources: {
    deck: 5,
    cable: 8,
    bolts: 10,
    c2: 4
  },
  collectibles: ["bread", "deck", "cable", "bolts", "c2"],
  obstacles: ["case", "cable_loop", "mic_stand", "box", "cart"],
  unlocksAfterComplete: ["wedding_tent"],
  intro: "До запуска 10 минут. Завхоз уже подозревает неладное.",
  resultPhrases: {
    perfect: "Сцена собрана. Завхоз почти улыбнулся.",
    good: "Мероприятие запущено. Один кабель остался лишним.",
    bad: "Запустили, но техдир теперь разговаривает с кофром."
  }
}
```

## 10. Спавн объектов

На v0.1 используем простую генерацию по таймеру.

Правило:

```text
каждые 0.7–1.2 сек появляется объект
70% collectible
30% obstacle
```

Ограничения:

- не спавнить препятствия сразу на всех трёх дорожках;
- не создавать безвыходные ситуации;
- давать игроку окно для реакции;
- не ставить два препятствия подряд без паузы;
- к концу уровня немного повышать сложность.

## 11. Столкновения

Логика столкновения:

```text
если объект на той же дорожке
и x объекта рядом с x игрока
и игрок не выполнил нужное уклонение
→ столкновение
```

Примеры:

```text
case        → jump
cable_loop  → jump
box         → jump
mic_stand   → lane_change
cart        → lane_change
```

Для v0.1 достаточно прямоугольной / радиусной проверки, без пиксель-перфект коллизий.

## 12. Финиш уровня

Уровень заканчивается по дистанции / прогрессу:

```text
distance >= level.distance или elapsedTime >= level.duration
```

После финиша:

- спавн объектов останавливается;
- игрок получает состояние `finished`;
- открывается ResultScreen;
- прогресс сохраняется.

## 13. Расчёт результата

Считать:

```text
хлеб
ресурсы
косяки
процент выполнения
оценка S/A/B/C/D
```

Базовая формула:

```text
resourcePercent = собранные нужные ресурсы / нужные ресурсы
mistakePenalty = количество ошибок * 10%
finalPercent = resourcePercent - mistakePenalty
```

Оценки:

```text
S: 95–100%
A: 80–94%
B: 65–79%
C: 45–64%
D: ниже 45%
```

## 14. Сохранение

Храним в `localStorage`.

Ключ:

```text
packit_run_save_v1
```

Формат:

```js
{
  version: 1,
  bread: 0,
  unlockedLevels: ["dk_almost_ready"],
  completedLevels: {
    dk_almost_ready: {
      bestGrade: "A",
      bestScore: 1230,
      completedAt: "2026-06-03T00:00:00.000Z"
    }
  },
  settings: {
    sound: true,
    music: true,
    vibration: true
  }
}
```

## 15. Логика открытия уровней

Для v0.1 достаточно:

```text
ДК пройден → открывается Свадьба
```

Полная будущая логика:

```text
ДК пройден → открывается Свадьба + Спаниель
Свадьба пройдена → открывается Большой концерт
Большой концерт пройден → открывается Детская комната
Детская комната пройдена → открывается скин “Домашний техдир”
```

## 17. Разделение ответственности

Правило:

```text
данные отдельно
рендер отдельно
логика отдельно
экраны отдельно
сохранения отдельно
```

Запрещено:

- рисовать всё напрямую в `Game.js`;
- хранить тексты внутри логики;
- хардкодить уровни в `GameScreen`;
- смешивать input, physics, render и storage в одном файле;
- делать временную архитектуру “потом перепишем”.

## 18. Renderer v0.1

Даже если графика временная, renderer должен быть готов к будущей замене примитивов на ассеты.

У объектов должен быть `visualKey`.

Пример:

```js
{
  id: "case",
  type: "obstacle",
  visualKey: "flight_case"
}
```

Сейчас `flight_case` рисуется canvas-примитивом. Позже он может стать PNG/WebP/SVG-ассетом без изменения игровой логики.

## 19. Чеклист готовности v0.1

v0.1 считается готовой, если:

- игра открывается через `index.html`;
- есть главное меню;
- есть выбор уровней;
- первый уровень запускается;
- хомяк виден и управляется;
- есть 3 дорожки;
- работает смена дорожек;
- работает прыжок;
- работает подкат;
- объекты спавнятся и едут справа налево;
- хлеб и ресурсы собираются;
- препятствия наносят косяки;
- уровень завершается;
- появляется экран результата;
- результат сохраняется в localStorage;
- после прохождения ДК открывается Свадьба;
- код разделён по модулям;
- нет тяжёлых зависимостей;
- игра не требует сборки.

## 20. Не входит в v0.1

Не входит:

- полноценный магазин;
- склад;
- боссы;
- спаниель в геймплее;
- финальные ассеты;
- музыка;
- онлайн-рекорды;
- мобильная вертикальная версия;
- донат;
- авторизация;
- редактор уровней.
