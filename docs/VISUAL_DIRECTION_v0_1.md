# PACK.IT RUN — Visual Direction v0.1

Дата фиксации: 2026-06-03

## 1. Главный визуальный принцип

**PACK.IT RUN** должен выглядеть как мультяшная техно-изометрическая аркада, где маленький серьёзный хомяк спасает большие хаотичные мероприятия, а после финала проваливается в сюрреалистичную детскую комнату, где срач стал живым объектом.

Ключевое ощущение:

```text
маленький герой в большом хаотичном техмире
```

Стиль:

```text
мультяшная техно-изометрия
```

Не делаем:

- пиксель-арт;
- реализм;
- унылые серые placeholder-квадраты;
- совсем детскую флешку;
- плоский динозаврик-раннер.

## 2. Камера и формат

Формат:

```text
1280 × 720
landscape-first
```

Камера:

- горизонтальный раннер;
- хомяк слева / центр-слева;
- мир едет справа налево;
- три дорожки уходят в глубину;
- псевдо-изометрия создаётся через смещение, масштаб и слои.

Базовая композиция:

```text
       дальняя дорожка
          ─────────────────────
      средняя дорожка
    ─────────────────────
  ближняя дорожка
─────────────────────

       🐹
```

## 3. Базовая разметка экрана

Логическая база:

```text
baseWidth: 1280
baseHeight: 720
```

Разделение:

```text
HUD сверху: 80 px
игровая зона: 560 px
нижняя строка событий / подсказок: 80 px
```

Схема:

```text
┌─────────────────────────────────────────────┐
│ HUD: хлеб, ресурсы, косяки, прогресс         │
├─────────────────────────────────────────────┤
│                                             │
│              canvas gameplay                │
│                                             │
├─────────────────────────────────────────────┤
│ фраза / событие / подсказка                  │
└─────────────────────────────────────────────┘
```

## 4. Псевдо-изометрические дорожки

Дорожки не должны выглядеть как три плоские горизонтальные полосы. Они должны ощущаться как площадка под углом.

Рекомендуемые базовые параметры:

```text
дальняя:  y = 270, scale = 0.82, xOffset = +80
средняя:  y = 360, scale = 1.00, xOffset = 0
ближняя:  y = 455, scale = 1.18, xOffset = -80
```

При смене дорожки хомяк должен двигаться диагонально.

Слои отрисовки:

```text
сначала дальняя дорожка
потом средняя
потом ближняя
потом HUD / эффекты поверх
```

Объекты ближней дорожки должны быть чуть крупнее и ниже. Объекты дальней дорожки — чуть меньше и выше.

## 5. Общая UI-палитра

Базовое настроение UI: тёмная техсводка с яркими сценическими акцентами.

Рекомендуемая палитра:

```text
#101722 — основной фон
#182235 — панели
#25344d — карточки
#f4b942 — хлеб / главный акцент
#67e8f9 — техно-свет
#ef4444 — опасность / protect
#84cc16 — успех
#f8fafc — основной текст
#94a3b8 — вторичный текст
```

Принципы:

- фон тёмный, но не чёрный;
- панели читаемые;
- хлебный жёлтый — главный тёплый акцент;
- опасности — красный / тёмно-красный;
- технологические подсветки — cyan / blue;
- UI не должен спорить с игровыми объектами.

## 6. UI-стиль

Интерфейс должен ощущаться как мини-техсводка, но мультяшно.

Формы:

- скруглённые карточки;
- тонкие контрастные обводки;
- мягкие тени;
- компактные бейджи;
- крупные читаемые кнопки.

Текст:

- короткие фразы;
- хороший контраст;
- без мелкого мусора;
- юмор через статусы и вердикты.

HUD должен быть понятен за секунду:

```text
Хлеб
Ресурсы
Косяки
Прогресс уровня
```

## 7. Главное меню

Главное меню не должно быть пустым.

Композиция:

```text
слева: название игры
центр: хомяк на маленькой сцене / кофре / ящике
справа: кнопки
фон: монтажная площадка с мягким светом
```

Заголовок:

```text
PACK.IT RUN
Хомяк на монтаже
```

Кнопки:

```text
Играть
Уровни
Склад
Магазин
Настройки
```

Снизу маленькая случайная фраза:

```text
Сегодня дедлайн выглядит подозрительно.
```

## 8. Экран выбора уровней

Карточки уровней должны выглядеть как проектные карточки.

Пример:

```text
┌──────────────────────────────┐
│ ДК “Почти готово”             │
│ Сцена, кабели, завхоз         │
│ Лучший результат: A           │
│ [Старт]                       │
└──────────────────────────────┘
```

Заблокированная детская комната:

```text
┌──────────────────────────────┐
│ ???                           │
│ ТЗ отсутствует                │
│ Открывается после концерта    │
│ [Заблокировано]               │
└──────────────────────────────┘
```

После открытия:

```text
Детская комната
Генеральная уборка невозможна
```

## 9. Главный герой — хомяк

Хомяк должен быть крупным, читаемым и выразительным.

Образ:

```text
маленький боевой хомяк
каска
сигнальная жилетка
пояс с инструментами
серьёзные глаза
маленькие лапы
пузико
хлеб как священный артефакт
```

Силуэт:

- круглая голова;
- маленькие уши;
- пухлое тело;
- короткие лапы;
- каска сверху;
- жилетка ярким пятном.

Состояния анимации:

```text
idle / run
jump
slide
hit
celebrate
```

На v0.1 можно рисовать хомяка canvas-примитивами, но стилизованно:

- тело — округлая форма;
- каска — дуга;
- жилетка — яркая трапеция;
- глаз — точка;
- хлеб — маленький скруглённый кусочек.

## 10. Помощник — шоколадный русский спаниель

В v0.1 спаниеля можно ещё не добавлять в геймплей, но визуально и архитектурно его надо заложить.

Образ:

```text
шоколадный русский спаниель
длинные уши
боевой, но добрый
маленькая каска опционально
иногда несёт хлеб
```

Роль в будущих версиях:

- появляется на главном экране после прохождения ДК;
- появляется в ResultScreen;
- помогает как активный companion;
- в бонусной детской комнате может как помогать, так и случайно усиливать хаос.

## 11. Уровень 1 — ДК “Почти готово”

Цвета:

```text
бордовый
пыльный золотой
тёмное дерево
серый кофр
тёплый свет
```

Фон:

- сцена ДК;
- кулисы;
- боковой прожектор;
- старый деревянный пол;
- кофры;
- микрофонные стойки;
- пыль в лучах света.

Дорожки:

- деревянные / сценические полосы с перспективой;
- мягкий тёплый свет;
- тени от кофров и стоек.

Препятствия:

- кофр — серый ящик с металлическими уголками;
- кабельная петля — чёрная петля на полу;
- микрофонная стойка — тонкая, но читаемая;
- коробка проводов — хаотичный ящик;
- тележка — маленькая платформа на колёсах.

Collectibles:

- хлеб — золотистый;
- кабель — моток;
- C2 — маленький металлический крепёж;
- болты — блестящие точки;
- настил — мини-плитка.

## 14. Бонус — Детская комната

Главный принцип:

```text
комедийный кошмар родителя и техника одновременно
```

Это не просто детская. Это сюрреалистичный объект, где домашний срач ведёт себя как живой монтажный хаос.

Цвета:

```text
яркий жёлтый
игрушечный синий
розовый
зелёный
красный
тёмная фиолетовая / синяя сюр-подложка
```

Фон:

- ковёр как дорожка;
- кровать / диван как backstage;
- плед как занавес;
- игрушечные коробки;
- кубики;
- носки на всём;
- LEGO как минное поле;
- карандаши как мини-фермы;
- зарядки как кабели;
- мягкие игрушки как комиссия.

Дорожки:

- визуально могут плыть;
- ковёр может сдвигаться;
- плед может перекрывать часть экрана;
- игрушки могут вываливаться;
- тени могут жить своей жизнью.

## 15. Сущность Срача

Визуально:

```text
полупрозрачная куча хаоса
из носков, фантиков, кубиков, LEGO, карандашей, зарядок и игрушек
с двумя светящимися глазами
не хоррор-монстр, а абсурдно смешная угроза
```

Она должна быть одновременно:

```text
жутковатая
смешная
узнаваемая
не слишком страшная
```

Финальная босс-форма:

```text
огромная куча хаоса на фоне комнаты
из неё торчит XLR, носок, плюшевый заяц, карандаш и кусок хлеба
```

## 16. Визуальная иерархия объектов

### Collectibles

Должны быть:

- яркие;
- маленькие;
- с лёгким свечением;
- приятные для сбора;
- хорошо отличимые от препятствий.

### Obstacles

Должны быть:

- крупнее collectibles;
- темнее / контрастнее;
- с опасной обводкой или тенью;
- читаемые заранее;
- не сливаться с дорожками.

### Powerups

Должны отличаться от ресурсов:

- пульсирующая обводка;
- сияние;
- значок;
- отдельный цветовой язык.

### Boss objects

Должны иметь опасный язык:

- красный;
- фиолетовый;
- предупреждающие маркеры;
- волны;
- вспышки.

## 18. Canvas-shape art на старте

Не ждать готовых ассетов. Первый визуал делаем через canvas-shape art, но аккуратно.

Рисуем не квадраты, а стилизованные примитивы:

- хомяк из кругов / овалов;
- каска дугой;
- жилетка многоугольником;
- кофр прямоугольником с уголками;
- кабель петлёй;
- хлеб маленькой скруглённой формой;
- ферма линиями;
- LED-модуль сеткой;
- саб кругом;
- LEGO кубиками.

Обязательно:

- цвет;
- тень;
- обводка;
- световой акцент;
- масштаб по дорожке.

Даже без спрайтов игра должна выглядеть “с характером”.

## 19. Путь к ассетам

Renderer должен быть устроен так, чтобы объект мог рисоваться двумя способами:

```text
сейчас: canvas primitive
потом: sprite image
```

У каждого объекта должен быть `visualKey`.

Пример:

```js
{
  id: "case",
  type: "obstacle",
  visualKey: "flight_case"
}
```

Сейчас `flight_case` рисуется примитивом. Позже `flight_case` может стать PNG/WebP/SVG без изменения gameplay logic.

## 20. Renderer-правила

В первом коде нужны отдельные слои / классы:

```text
IsoProjector
ThemeRenderer
ObjectRenderer
HudRenderer
ScreenRenderer
```

Запрещено:

- рисовать всё прямо в `Game.js`;
- смешивать логику столкновений и отрисовку;
- хардкодить цвета объектов внутри gameplay logic;
- делать визуал без `visualKey`;
- строить UI только внутри canvas, если проще оставить часть UI в HTML.

## 21. Визуальные приоритеты v0.1

В v0.1 важнее всего:

1. читаемые 3 дорожки;
2. понятный хомяк;
3. понятное отличие ресурсов от препятствий;
4. приятный тёмный UI;
5. характерный ДК-уровень;
6. отсутствие ощущения “серой технической демки”.

Можно временно упростить:

- спаниеля;
- фоновые детали;
- сложные эффекты;
- анимации;
- боссов;
- магазин.

Нельзя упрощать до уровня:

```text
белый фон + прямоугольники + без атмосферы
```

## 22. Основной визуальный фикс

Фиксируем направление:

> PACK.IT RUN — это мультяшная техно-изометрическая аркада с тёмной сценической атмосферой, хлебным юмором, выразительным хомяком-техником, шоколадным спаниелем и бонусной детской комнатой, где бытовой срач превращается в живой сюрреалистичный объект.
